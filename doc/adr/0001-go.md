# 0001 — Go as the implementation language

Status: accepted

## Context

The toolkit being replaced was about 5,900 lines of Bash and Tcl across 27
executables. A review scored four candidate languages against the requirements,
with prototypes: Go 8–8.5, Rust 7–8, Python 6, TypeScript dropped.

What the program actually is: a command line tool that runs many subprocesses
in parallel, speaks HTTP and TLS to service processors, handles SSH keys, and
has to be installed on the laptops of a team that writes mostly Bash.

## Decision

Go, minimum 1.26, built with `CGO_ENABLED=0`.

## Why

- **A static binary.** No interpreter, no virtual environment, no libc
  dependency. One file that runs on RHEL 8 through 10, Fedora and macOS. This
  is what ruled out Python, whose bundle was 43 MB and took six seconds to
  unpack on first run — long enough to be felt in tab completion.
- **The patterns transfer.** cobra, a versioned configuration scheme, contexts
  in the style of kubeconfig: all of it is well-trodden in Go and the team has
  read kubectl's help text before.
- **Readable by a Bash-first team.** Rust scored close and has the better
  configuration story, but ownership and async are a steep climb for people who
  will contribute occasionally. A tool nobody on the team can change is worse
  than one that is slightly less elegant.
- **The libraries exist.** `filippo.io/age` is the reference age
  implementation, `golang.org/x/crypto/ssh` can reach old service processors
  that a system ssh refuses, and the standard library covers HTTP, TLS and
  process handling.

## Costs

- **No node set library exists.** ClusterShell's semantics had to be ported.
  See [0002](0002-own-nodeset-engine.md).
- **YAML needs care.** `goccy/go-yaml` is the best available, but a literal
  with a leading zero has to be handled by the loader rather than trusted to
  the parser.
- **Go 1.26 is the edge of what RHEL's go-toolset ships.** A distribution build
  with cgo and an OpenSSL FIPS provider behaves differently from the static
  release build, so the release binary is the supported artefact.

## Notes

Go 1.26 is what `go.mod` requires. The toolchain downloads itself when a
machine has an older one, so this is not a barrier to building.
