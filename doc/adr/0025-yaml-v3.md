# 0025 — Read YAML with yaml.v3

Status: accepted

## Context

[0001](0001-go.md) named `goccy/go-yaml` the best YAML library available, with
the loader deciding what a literal with a leading zero is. Every command reads
the whole configuration, and a shell completion is a command too. With a
`NodeInventory` of 10,000 nodes, goccy took 0.43 s and allocated 293 MB to
parse the files: more than half of a command that otherwise does nothing, and
most of its memory. The MCP server keeps what it read while the files stay the
same, but the command line reads them every time.

goccy also took a second document marker after a document of comments alone for
the end of the stream, and dropped every document after it without an error. The
loader split the stream itself to get around it; the reader of Secret documents
did not. And a byte order mark became part of the first key.

## Decision

- **`go.yaml.in/yaml/v3`**, the YAML organisation's continuation of
  `gopkg.in/yaml.v3`, which the module already had through cobra's
  documentation generator. Each document is decoded into a `yaml.Node`, which
  carries the line and column of every key, and the loader turns that into
  the plain tree and the positions it built before. The sops metadata of a
  Secret document is read from the same nodes.
- **The loader decides what a scalar is, as it did.** A number is a whole
  number in decimal, or after `0x`, `0o` or `0b`, or one with a decimal point.
  A literal with a leading zero is text, and so are `1e3`, `0X1F`, a whole
  number beyond 64 bits and a date, which yaml.v3 reads as numbers or times.
  A tag of the YAML types is not followed, so `!!str 8` is 8 as it was; a
  site's own tag makes the value text. A key is untagged text. An alias, an
  infinity and not-a-number are refused.
- **Compared before the switch.** Both parsers read every YAML file in the
  repository, the YAML in the manual and in the tests, and some 700 written to
  find where they part: scalars of every kind as values, keys and list items,
  and streams with empty documents, markers, tags, block scalars and errors.
  They read the same tree, with the same positions, except where this record
  says otherwise.

## Costs

- **YAML goccy took and yaml.v3 refuses, as the YAML specification does:** a
  block scalar inside `[...]` or `{...}`, `[- a]`, an unquoted value that
  begins with `%` (goccy refused it on the first line and took it on the
  others), and a stream of nothing but `...`. A site that wrote one has to
  quote it or write it out.
- **`+.inf` is refused**, as `.inf` and `-.inf` were; goccy read it as text.
- **Other readings change for the better:** an explicit key, `? a`, is read;
  a column after a tag is counted from the line's start, where goccy was one
  short; a byte order mark is not part of the first key; and a Secret
  document after an empty one is read rather than reported missing.
- **Error messages are yaml.v3's**, `yaml: line 3: did not find expected key`,
  without goccy's excerpt of the file. The file name and the line are still
  there.
- **yaml.v3 is maintained** by the YAML organisation as `go.yaml.in/yaml/v3`;
  `gopkg.in/yaml.v3` is not. v4 is a release candidate, and a move to it is
  another record.
