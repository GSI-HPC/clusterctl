# 0008 — LGPL-3.0-or-later

Status: accepted

## Context

The shell scripts carried GPL-3.0-or-later headers, and the repository had no
licence file at all. The review flags this: binaries that bundle LGPL, MPL and
Apache code should not ship without one.

## Decision

`LGPL-3.0-or-later`, as `COPYING` (the GNU GPL version 3) and `COPYING.LESSER`
(the additional permissions that make it the Lesser GPL), which is the layout
the Free Software Foundation recommends for LGPL works. Every source file
carries `SPDX-License-Identifier: LGPL-3.0-or-later`.

## Why the Lesser variant

The module offers `nodeset` as a package other programs can import
([0010](0010-public-nodeset-package.md)). Under the plain GPL, importing it
would make the importing program GPL — which is a real barrier for a site with
an internal tool, and would leave the Go ecosystem without a node set
implementation for a second time.

The Lesser GPL keeps changes to this code copyleft while letting a program use
it as a library. For a small, factual library that is the outcome that serves
the most people.

## Compatibility

The dependencies are BSD-3-Clause, MIT and Apache-2.0. All are compatible with
LGPL-3.0, and a combined work may be distributed under it.

## Note on static linking

The binary is statically linked. The Lesser GPL's relinking obligation is about
combining an LGPL library with a work that is not covered by it; a binary whose
own source is entirely LGPL and published is not in that position. A downstream
that links this code into a proprietary program is, and section 4 of the
licence says what it has to provide.

## Note on relicensing

The shell scripts were GPL-3.0-or-later and "or later" does not permit moving
to the Lesser GPL; only the copyright holders can. The Go code here is new
work, not a translation of those scripts, and the shell tree was removed rather
than carried forward. A site that needs the original terms should take them
from the history, where they remain under GPL-3.0-or-later.
