# Reaching a host

clusterctl drives the OpenSSH client rather than speaking SSH itself. That
keeps `ProxyJump`, `ControlMaster`, Kerberos, the agent, PKCS#11 tokens and the
administrator's own configuration working exactly as they do from a shell, and
it keeps this program out of the business of implementing a security protocol.

## A command never becomes a string

This is the single most important thing in the program.

The shell toolkit built a remote command by joining its arguments with spaces
and handing the result to `eval`. Three things went wrong:

- `clusterctl exec -- echo '*.log'` expanded the glob **on the workstation**,
  against whatever files happened to be in the current directory.
- Repeated whitespace was collapsed.
- An apostrophe broke the command.

Here, the argument vector is quoted once by `internal/shellquote`, handed to
`ssh` as a **single argument**, and split back by the remote shell into exactly
the arguments that were given. The property is checked against a real shell in
the tests: every vector that goes in comes back out unchanged.

```
$ clusterctl login --dry-run install -- ls '/srv/*.log'
ssh -F ~/.local/state/clusterctl/ssh_config -A root@installer.hpc.example.org -- ls '/srv/*.log'
```

A script is sent as one `bash -c '<script>'` argument for the same reason, and
standard input is left free for payloads. Sharing one stream between a script
and its data corrupts both.

One argument is capped at 131072 bytes by the kernel. A command over that is
reported, with the advice to send the payload over standard input instead.

## The generated ssh configuration

Every connection is made with `-F` and a file clusterctl generates into its
state directory. Its shape is load-bearing:

```
# Generated by clusterctl. Edits are overwritten.

# role mgmt: Management network gateway
Host mgmt-gw.example.org
  User alice_adm
  ForwardAgent yes
  ControlMaster auto
  ControlPath  ~/.local/state/clusterctl/cm-%C
  ControlPersist 300

Host *
  UserKnownHostsFile /etc/clusterctl/ssh-known-hosts
  StrictHostKeyChecking yes
  CheckHostIP no
  HashKnownHosts no
  ConnectTimeout 10
  ...

Include /etc/ssh/ssh_config
```

**The settings come first and the includes last.** ssh keeps the first value it
obtains for a keyword, so what clusterctl needs wins and everything it does not
set still comes from the system and user configuration. Leaving the include out
would drop RHEL crypto policies, `GSSAPIAuthentication yes` and FreeIPA host
certificates on the floor.

**A host block matches the real host name**, never an invented alias. An alias
with a `HostName` would stop the administrator's own blocks for that host from
matching.

**Trust settings live in the file, not in `-o` options**, because `-o` does not
reach the hops of a `ProxyJump`.

**`CheckHostIP no` is not optional.** With it on, ssh appends address-based
entries to the shared host key file behind clusterctl's back, without taking a
lock, which corrupts a file the team keeps in version control.

**`PubkeyAcceptedKeyTypes`, not `PubkeyAcceptedAlgorithms`.** OpenSSH 8.0,
which RHEL 8 ships, aborts on the newer keyword even inside a `Host` block that
does not match. The old spelling is understood everywhere.

**Multiplexing is opt-in per role.** A gateway or a hub is worth a shared
connection; a master per compute node runs into sshd's `MaxStartups` at scale.

An include for a file that does not exist is left out, so ssh never fails over
a path a site does not use.

## Timeouts

A command timeout is enforced **on the target** with `timeout -k`. Killing the
local ssh does not stop the remote process, so a command that hangs would
otherwise keep running on the node with nothing watching it.

Connection timeouts and attempts are ssh's own, set in the generated
configuration.

## Fan-out

`internal/fanout` runs one request on many targets with a bounded number in
flight. Two properties are deliberate:

- **Results come back in target order** whatever order they finished in, so two
  runs of the same command print the same thing.
- **One failing node does not stop the others.** The point of asking a hundred
  nodes something is to learn about all hundred.

`--dedup` collapses the nodes that answered the same thing, which turns a
thousand replies into the few worth reading.

For sets larger than `fanout.offloadAbove`, the configuration can name a host
role to run `clush` on instead, which keeps sshd's connection limits out of the
picture entirely.

## Secrets

A password never appears in a remote argument vector. `ps` on a shared gateway
shows every argument to every user, and the shell toolkit put the BMC password
there on every call.

Instead the secret is streamed over standard input into a wrapper that writes
it to a file only its owner can read and removes it again whatever happens:

```sh
set -eu
umask 077
secret=$(mktemp "${TMPDIR:-/tmp}/clusterctl.XXXXXXXX")
trap 'rm -f "$secret"' EXIT INT TERM
cat > "$secret"
/usr/sbin/ipmipower --config-file "$secret" --hostname 'exe[1-10]' --off
```

The same path carries the cluster's own secrets: an age encrypted file, or a
value of a sops encrypted Secret document, is decrypted into memory on the
workstation and written onto the node over standard input, so the plaintext
never touches either disk.

## Host keys

One file is the site's trust anchor, kept in version control, and every
connection is checked against it.

Keys are collected by starting an SSH handshake and abandoning it the moment
the server presents its key, so no credentials are involved. The file is always
rewritten completely, under a lock, and sorted, so two administrators
refreshing at once cannot lose an entry and a diff stays readable.

`hostkey verify` reports a changed key and exits non-zero. Whether that is a
reinstalled machine or something worth investigating is not for a program to
decide.
